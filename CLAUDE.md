# szimnau.dk — Development Guide

Astro 6 + Tailwind CSS 4 static site on Cloudflare. Locales: `en` (default), `da`, `de`. All routes are locale-prefixed (`/en/`, `/da/`, `/de/`).

Layout: pages in `src/pages/[lang]/`, layouts `Base.astro` and `BlogPost.astro`, SEO in `src/components/SEO.astro`, strings in `src/i18n/ui.ts`, posts in `content/blog/{en,da,de}/`.

## Build & Validate

```bash
npm install
./node_modules/.bin/astro build   # must complete with 0 errors before any commit
npm run validate       # source + SEO checks on dist/ (run after build)
npm run validate:src   # source checks only, runs as pre-commit hook
```

`scripts/validate.mjs` enforces on every built page: title format `[Title] | szimnau.dk`, description 120-160 and unique, robots `index, follow`, canonical, hreflang (`en-US`, `da-DK`, `de-DE`, `x-default`, absolute with trailing slash), OG/Twitter tags, existing absolute og:image, one h1 with no skipped levels, hero attributes (`width="768" height="432" loading="eager" fetchpriority="high" decoding="async"`). Source rules: required frontmatter, `translationKey` in all 3 locales, every `/blog-images/` file exists and is git-tracked. Voice findings are warnings. Fix what it reports. Skip the hook once with `git commit --no-verify`.

Shiki: use `jinja`, never `jinja2` (wrong names disable highlighting and warn).

## SEO rules the validator does not check

- Site origin is `https://szimnau.dk` (no `www`). `astro.config.mjs` `site` and the `public/robots.txt` line `Sitemap: https://szimnau.dk/sitemap-index.xml` must match. Never hardcode the origin in components: use `Astro.site?.origin ?? 'https://szimnau.dk'`.
- Every page renders (via `SEO.astro`) `WebSite` schema (no `potentialAction` without a real search endpoint) and `Person` schema (Rolf Szimnau, url = origin). About pages add their own `Person` with `jobTitle`.
- Blog posts render (via `BlogPost.astro`) `BlogPosting` (headline, description, datePublished, dateModified, author, publisher, absolute image, keywords, inLanguage), `BreadcrumbList` (Home → Blog → Post, lang-prefixed, trailing slash) and `FAQPage` when `faqs` exist (with `inLanguage: lang`).
- Never use a heading tag for visual styling. Use `<p>` or `<span>`.
- Blog card thumbnails: `loading="lazy" decoding="async"` with explicit `width` and `height`. All `og:image` and `BlogPosting.image` values are absolute (prepend `siteOrigin`).
- Internal links are lang-prefixed (`/en/blog/`). External editorial links: `rel="noopener noreferrer"` only, no `nofollow`. Paid links: `rel="sponsored"`. Never add `nofollow` in `HardwareLab.astro`.
- `public/og-default.png` (1200×630), `robots.txt` and `ai.txt` must stay. `/llms.txt` is generated by `src/pages/llms.txt.ts`: never add a static copy to `public/`.
- Every new page needs `en/`, `da/`, `de/` versions. `faqs` are written in the post's language.

## New blog posts

Use the `new-blog-post` skill. New images are `.webp`. `git add` every referenced image, or Cloudflare deploys a 404'd `<img>`.

## Blog Voice — Non-Negotiable

Every post reads like a person wrote it, not a content system.

- No uniform structure. Don't open every post with the same H2 sequence. Fit structure to content.
- No polished-AI phrasing ("this approach yields", "a powerful pattern", "seamlessly integrates"). Write it like you're explaining it to someone in the next room.
- No "What's Next" / "Conclusion" / "Wrapping Up" ending. End when the story ends, on a specific observation.
- Vary sentence length.
- Open with the problem, not the solution.
- One specific, real anecdote per post: a date, a number, a concrete moment.
- Admit what doesn't work.

**DA and DE are written from scratch, never translated from EN.** Different anecdotes, phrasing and native idioms. Applies to all site copy (hero, about, `ui.ts`).

DA/DE traps to check before finalizing a sentence:
1. Compounds and orthography: Danish compounds are one word with no English plural-s (`detektionslog`), numbers as one word (`niogtyve`), time as `kl. 16.30`.
2. Borrowed metaphors: don't translate an English image word-for-word (EN "a crutch, not a fix" → DA "krykke"). Use the native word for the concept (DA `nødløsning`, DE `Notlösung`).

## Deployment

`git push` to GitHub (`RolfSzimnau/szimnau-dk`). Cloudflare Pages builds and deploys. **Never use Wrangler CLI to deploy.** Static output to `dist/`.
