**Update, November 2026:** Home Assistant 2026.11 deprecated the old `notify.android_tv_*` action, and it stops working in version 2027.5, so the TV example now uses `nfandroidtv.send_message`. I also corrected the rest of the post to match my setup today: those changes have nothing to do with the new version. The automation no longer saves a still to `/local` either, because files there can be fetched without logging in.

For about two weeks after installing the Sentinel camera, I had motion notifications turned on. Every notification said "Motion detected." Birds, shadows, a plastic bag blowing past the lens at 3am. I turned them all off and left the camera sitting there doing nothing useful for another month.

The fix was simpler than I expected: trigger on person and vehicle only (not raw motion), and give the notification three buttons that actually do something.

## What the integration gives you

After adding the camera, HA creates a set of binary sensors from the onboard detection:

```
binary_sensor.sentinel_motion
binary_sensor.sentinel_person
binary_sensor.sentinel_animal
binary_sensor.sentinel_vehicle
```

Person and vehicle come from the camera's own AI chip. Reasonably accurate: better than pure motion, not perfect. The animal sensor has caught actual foxes and, memorably, a large plastic bag moving in a way that apparently seemed alive.

## One automation for both triggers

Person and vehicle events go through a single automation in `parallel` mode, so a person and a car can each send an alert at the same time. Each type has its own cooldown: the time of the last alert goes into an `input_datetime`, and the template condition drops anything within 60 seconds of it.

```yaml
alias: "Sentinel: Camera & Notification"
mode: parallel
max_exceeded: silent
trigger:
  - platform: state
    entity_id: binary_sensor.sentinel_person
    from: "off"
    to: "on"
    id: person
  - platform: state
    entity_id: binary_sensor.sentinel_vehicle
    from: "off"
    to: "on"
    id: vehicle
variables:
  notif_title: "{{ '\U0001F697 Vehicle at the driveway' if trigger.id == 'vehicle' else '\U0001F464 Person at the driveway' }}"
  notif_message: "{{ 'Sentinel detected a vehicle' if trigger.id == 'vehicle' else 'Sentinel detected a person' }}"
  cooldown_entity: "{{ 'input_datetime.sentinel_last_vehicle_notification' if trigger.id == 'vehicle' else 'input_datetime.sentinel_last_person_notification' }}"
condition:
  - condition: state
    entity_id: input_boolean.sentinel_notifikation_lydlos
    state: "off"
  - condition: template
    value_template: >-
      {% set last = states(cooldown_entity) %}
      {% if last in ['unknown', 'unavailable', ''] %}
        true
      {% else %}
        {{ (now().timestamp() - as_timestamp(last, 0)) > 60 }}
      {% endif %}
action:
  - action: notify.mobile_app_pixel_10
    data:
      title: "{{ notif_title }}"
      message: "{{ notif_message }}"
      data:
        ttl: 0
        priority: high
        channel: Security
        importance: high
        tag: sentinel_alert
        image: /api/camera_proxy/camera.sentinel_snapshots_clear
        actions:
          - action: URI
            title: View Camera
            uri: homeassistant://navigate/nyt-mobil/overvagning
          - action: sentinel_flood_on
            title: Turn on Flood
          - action: sentinel_mute_30
            title: Mute 30 min
        clickAction: /nyt-mobil/overvagning
  # the same call goes to the other two devices
  # the TV step goes here, see below
  - action: input_datetime.set_datetime
    target:
      entity_id: "{{ cooldown_entity }}"
    data:
      datetime: "{{ now().strftime('%Y-%m-%d %H:%M:%S') }}"
```

Two phones and a tablet get a call each with the same content: a still from `camera.sentinel_snapshots_clear` and three buttons.

## The mute toggle

The first condition is `input_boolean.sentinel_notifikation_lydlos` (notification mute) being `off`. It's simpler than an `armed_away` condition: no alarm panel required, it works regardless of home or away state, and the notification itself can flip it via the Mute button.

A separate automation turns it off again after 30 minutes, so I never have to remember to do it.

## Action buttons

The notification carries three buttons:

- **View Camera**: deep-links to the Security view in the HA companion app
- **Turn on Flood**: turns on `light.sentinel_floodlight` through a separate automation listening for the `sentinel_flood_on` mobile action event
- **Mute 30 min**: turns on the mute toggle through that same automation, and the reset below turns it off after 30 minutes

The Mute button only turns the toggle on. The reset is its own automation, so it also works when the toggle gets turned on some other way:

```yaml
alias: "Sentinel: Reset Mute"
trigger:
  - platform: state
    entity_id: input_boolean.sentinel_notifikation_lydlos
    to: "on"
action:
  - delay:
      minutes: 30
  - action: input_boolean.turn_off
    target:
      entity_id: input_boolean.sentinel_notifikation_lydlos
```

## Fire TV notification

The same automation also pushes to the TV in the living room:

```yaml
  - action: nfandroidtv.send_message
    continue_on_error: true
    target:
      entity_id: notify.android_tv_fire_tv_192_168_1_40
    data:
      message: "{{ '\U0001F697 Vehicle detected at the driveway' if trigger.id == 'vehicle' else '\U0001F464 Person detected outside' }}"
      image:
        media_content_id: media-source://camera/camera.sentinel_fluent
        media_content_type: image/jpeg
      interactive: true
```

HA takes a fresh frame from the camera and sends the image itself to the TV, so there is no URL and no cached still from the previous event. `interactive: true` makes it pop up even during playback. Keep `continue_on_error: true`: without it, a TV that is switched off stops the run, and the steps after it never happen.

## The dashboard

![The Security view on the tablet: the live garden camera on the left, six status chips and a Recent events list on the right](/blog-images/sentinel-security-view.webp)

On the tablet the Security view has two columns. The left one is the camera card with the live stream from `camera.sentinel_fluent`. The notifications attach a still from a different entity, `camera.sentinel_snapshots_clear`. The menu row above the image belongs to the card itself, not to my automations.

The right column has two parts. The chips show what the sensors say right now: grey and "Person clear" while a sensor is `off`, a coloured icon and "Person detected" while it is `on`. The template follows the sensor, so nothing has to reset the chip. Flood and Audio are buttons: they toggle the floodlight (the same light as the Turn on Flood button in the notification) and the camera's audio recording. Below them, Recent events is the log. A markdown card prints the ten entries of `input_text.sentinel_event_log`, newest first. The Sentinel event log automation adds an entry each time one of the four sensors turns `on`, never when it goes back. How that works is in the post on a [detections-only event list](/en/blog/detection-event-log-home-assistant/). In the screenshot nothing is happening, so all four chips are grey and the list is full of older detections.

On the phone, the Security view stacks the camera at the top, four status chips for motion, person, animal and vehicle, and the same list of recent events. The chips all follow the same pattern:

```yaml
type: custom:mushroom-chips-card
chips:
  - type: template
    entity: binary_sensor.sentinel_person
    icon: mdi:walk
    icon_color: "{% if is_state('binary_sensor.sentinel_person','on') %}orange{% else %}disabled{% endif %}"
    content: Person
    tap_action:
      action: more-info
```

A small automation keeps the list by adding each new event to the front of an `input_text`:

```yaml
alias: Sentinel event log
mode: queued
max: 10
trigger:
  - trigger: state
    entity_id: binary_sensor.sentinel_person
    to: "on"
    id: person
  - trigger: state
    entity_id: binary_sensor.sentinel_motion
    to: "on"
    id: motion
  - trigger: state
    entity_id: binary_sensor.sentinel_animal
    to: "on"
    id: animal
  - trigger: state
    entity_id: binary_sensor.sentinel_vehicle
    to: "on"
    id: vehicle
action:
  - action: input_text.set_value
    target:
      entity_id: input_text.sentinel_event_log
    data:
      value: >-
        {% set m = {'person':'👤 Person','motion':'🏃 Motion','animal':'🐾 Animal','vehicle':'🚗 Vehicle'} %}
        {% set new = now().strftime('%H:%M') ~ ' ' ~ m[trigger.id] %}
        {% set old = states('input_text.sentinel_event_log') %}
        {% set items = ([new] + (old.split(' · ') if old not in ['unknown','unavailable',''] else []))[:10] %}
        {{ (items | join(' · '))[:255] }}
```

The list holds the last ten events, and motion counts too, so a busy afternoon pushes out the morning. The 255-character limit comes from `input_text` itself.
