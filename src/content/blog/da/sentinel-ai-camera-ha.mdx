De første par uger efter jeg satte Sentinel-kameraet op, havde jeg notifikationer for bevægelse slået til. Hver eneste sagde «Bevægelse registreret». Fugle, skygger, en plastikpose, der blæste forbi linsen klokken tre om natten. Jeg slog dem alle fra og lod kameraet hænge der uden at gøre meget nytte i endnu en måned.

Løsningen var enklere end ventet: reager kun på personer og køretøjer, ikke på al bevægelse, og giv notifikationen tre knapper, der faktisk gør noget.

## Det, integrationen giver

Når kameraet er tilføjet, opretter HA en række binære sensorer ud fra kameraets egen genkendelse:

```
binary_sensor.sentinel_motion
binary_sensor.sentinel_person
binary_sensor.sentinel_animal
binary_sensor.sentinel_vehicle
```

Person og køretøj kommer fra kameraets egen AI-chip. Ret præcis, bedre end ren bevægelse, men ikke fejlfri. Dyresensoren har fanget rigtige ræve og også en stor plastikpose, der åbenbart bevægede sig som et levende væsen.

## Én automation til begge udløsere

Hændelser med personer og køretøjer går gennem én automation i tilstanden `parallel`, så en person og en bil kan sende hver sin besked samtidig. Hver type har sin egen ventetid: tidspunktet for den seneste besked gemmes i en `input_datetime`, og skabelonbetingelsen afviser alt, der kommer inden for 60 sekunder.

```yaml
alias: "Sentinel: Kamera & Notifikation"
mode: parallel
max_exceeded: silent
trigger:
  - platform: state
    entity_id: binary_sensor.sentinel_person
    from: "off"
    to: "on"
    id: person
  - platform: state
    entity_id: binary_sensor.sentinel_vehicle
    from: "off"
    to: "on"
    id: bil
variables:
  notif_title: "{{ '\U0001F697 Bil ved indkørslen' if trigger.id == 'bil' else '\U0001F464 Person ved indkørslen' }}"
  notif_message: "{{ 'Sentinel har registreret et køretøj' if trigger.id == 'bil' else 'Sentinel har registreret en person' }}"
  cooldown_entity: "{{ 'input_datetime.sentinel_last_vehicle_notification' if trigger.id == 'bil' else 'input_datetime.sentinel_last_person_notification' }}"
condition:
  - condition: state
    entity_id: input_boolean.sentinel_notifikation_lydlos
    state: "off"
  - condition: template
    value_template: >-
      {% set last = states(cooldown_entity) %}
      {% if last in ['unknown', 'unavailable', ''] %}
        true
      {% else %}
        {{ (now().timestamp() - as_timestamp(last, 0)) > 60 }}
      {% endif %}
action:
  - action: notify.mobile_app_pixel_10
    data:
      title: "{{ notif_title }}"
      message: "{{ notif_message }}"
      data:
        ttl: 0
        priority: high
        channel: Overvågning
        importance: high
        tag: sentinel_alert
        image: /api/camera_proxy/camera.sentinel_snapshots_clear
        actions:
          - action: URI
            title: Se Kamera
            uri: homeassistant://navigate/nyt-mobil/overvagning
          - action: sentinel_flood_on
            title: Tænd Flood
          - action: sentinel_mute_30
            title: Lydløs 30 min
        clickAction: /nyt-mobil/overvagning
  # samme kald går til de to andre enheder
  # her kommer trinnet til TV'et, se længere nede
  - action: input_datetime.set_datetime
    target:
      entity_id: "{{ cooldown_entity }}"
    data:
      datetime: "{{ now().strftime('%Y-%m-%d %H:%M:%S') }}"
```

To telefoner og en tablet får hvert sit kald med samme indhold: et stillbillede fra `camera.sentinel_snapshots_clear` og tre knapper.

## Lydløs-kontakten

Den første betingelse er, at `input_boolean.sentinel_notifikation_lydlos` står på `off`. Den er enklere end en betingelse på `armed_away`: der skal ingen alarmcentral til, den virker, uanset om man er hjemme eller ude, og notifikationen kan selv slå den til via Lydløs-knappen.

En separat automation slår den fra igen efter 30 minutter, så jeg aldrig skal huske det.

## Knapperne i notifikationen

Notifikationen har tre knapper:

- **Se Kamera**: direkte link til visningen Overvågning i HA's Companion-app
- **Tænd Flood**: tænder `light.sentinel_floodlight` via en separat automation, der lytter efter handlingen `sentinel_flood_on` fra mobilen
- **Lydløs 30 min**: slår lydløs-kontakten til via samme automation, og nulstillingen herunder slår den fra igen efter 30 minutter

Lydløs-knappen slår kun kontakten til. Nulstillingen er sin egen automation, så den også virker, hvis kontakten bliver slået til på en anden måde:

```yaml
alias: "Sentinel: Nulstil Lydløs Tilstand"
trigger:
  - platform: state
    entity_id: input_boolean.sentinel_notifikation_lydlos
    to: "on"
action:
  - delay:
      minutes: 30
  - action: input_boolean.turn_off
    target:
      entity_id: input_boolean.sentinel_notifikation_lydlos
```

## Besked på Fire TV

Den samme automation sender også til TV'et i stuen:

```yaml
  - action: nfandroidtv.send_message
    continue_on_error: true
    target:
      entity_id: notify.android_tv_fire_tv_192_168_1_40
    data:
      message: "{{ '\U0001F697 Bil registreret ved indkørslen' if trigger.id == 'bil' else '\U0001F464 Person registreret udenfor' }}"
      image:
        media_content_id: media-source://camera/camera.sentinel_fluent
        media_content_type: image/jpeg
      interactive: true
```

HA henter selv et nyt billede fra kameraet og sender selve billedet til TV'et, så der er ingen URL og intet gammelt billede fra cachen. `interactive: true` får det til at dukke op, også mens noget afspilles. Behold `continue_on_error: true`: uden den stopper automationen, hvis TV'et er slukket, og trinnene efter kører aldrig.

**Opdatering, november 2026:** Home Assistant er ved at udfase den gamle handling `notify.android_tv_*`, som holder op med at virke i version 2027.5. Eksemplet her viser den nye form. Før var billedet en URL, og i stedet for `interactive: true` stod der `interrupt: 1`. Resten af indlægget passer nu også til automationen, som den kører i dag: en ventetid pr. type, ét kald pr. enhed, nulstilling af lydløs efter 30 minutter og en liste over seneste hændelser i stedet for logbogen. Automationen gemmer ikke længere et stillbillede i `/local`, fordi filer dér kan hentes uden login.

## Dashboard

Visningen Overvågning har kameraet øverst, statuskort for bevægelse, person, dyr og køretøj og en liste over de seneste hændelser. Statuskortene følger alle samme mønster:

```yaml
type: custom:mushroom-chips-card
chips:
  - type: template
    entity: binary_sensor.sentinel_person
    icon: mdi:walk
    icon_color: "{% if is_state('binary_sensor.sentinel_person','on') %}orange{% else %}disabled{% endif %}"
    content: Person
    tap_action:
      action: more-info
```

En lille automation holder styr på listen og lægger hver ny hændelse forrest i en `input_text`:

```yaml
alias: Sentinel event log
mode: queued
max: 10
trigger:
  - trigger: state
    entity_id: binary_sensor.sentinel_person
    to: "on"
    id: person
  - trigger: state
    entity_id: binary_sensor.sentinel_motion
    to: "on"
    id: motion
  - trigger: state
    entity_id: binary_sensor.sentinel_animal
    to: "on"
    id: animal
  - trigger: state
    entity_id: binary_sensor.sentinel_vehicle
    to: "on"
    id: vehicle
action:
  - action: input_text.set_value
    target:
      entity_id: input_text.sentinel_event_log
    data:
      value: >-
        {% set m = {'person':'👤 Person','motion':'🏃 Motion','animal':'🐾 Animal','vehicle':'🚗 Vehicle'} %}
        {% set new = now().strftime('%H:%M') ~ ' ' ~ m[trigger.id] %}
        {% set old = states('input_text.sentinel_event_log') %}
        {% set items = ([new] + (old.split(' · ') if old not in ['unknown','unavailable',''] else []))[:10] %}
        {{ (items | join(' · '))[:255] }}
```

Listen rummer de ti seneste hændelser, og bevægelse tæller med, så en travl eftermiddag skubber formiddagen ud. Grænsen på 255 tegn kommer fra `input_text` selv.
