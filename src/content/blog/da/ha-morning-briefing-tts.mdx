Hver morgen åbnede jeg Home Assistant-appen for at se dagens kalender, kigge på vejret og vurdere ud fra elprisen, om aftenen var et godt tidspunkt at starte opvaskemaskinen. Tre forskellige opslag før kaffen.

Morgenbriefingen erstattede det hele. Kl. 06:00 læser højttaleren i køkkenet dagens aftaler fra tre familiekalendere op, sammen med udetemperaturen, en påmindelse om affald, når det hentes i morgen, og den aktuelle elpris. Det hele tager cirka 15 sekunder.

## Hvad briefingen siger

På en typisk morgen lyder det sådan her:

> *"God morgen! I dag er det mandag. Temperaturen ude er 14 grader. Du har 2 aftaler i dag: tandlæge, teammøde. Husk: affald hentes i morgen. Elprisen er 0,42 kroner per kilowattime."*

På en rolig dag uden aftaler og uden affaldsafhentning lige forude bliver den kortet ned til vejr og pris. Der læses ikke noget op, hvis der ikke er noget at sige.

## Det centrale mønster: `calendar.get_events` med `response_variable`

De fleste vejledninger til automationer i Home Assistant stopper ved at udløse noget, når en kalenderaftale starter. Denne automation gør noget andet: den spørger selv kalenderen om dagens aftaler og bruger svaret i en template.

Handlingen `calendar.get_events` returnerer et struktureret svar, som kan gemmes i en variabel og bruges i de følgende trin:

```yaml
- action: calendar.get_events
  target:
    entity_id: calendar.rolf_szimnau_dk
  data:
    start_date_time: "{{ today_at('00:00') }}"
    end_date_time: "{{ today_at('23:59') }}"
  response_variable: kalender
```

Svaret er en dict med entitets-id'et som nøgle. Sådan får du fat i listen over aftaler:

```jinja
{% set events = kalender['calendar.rolf_szimnau_dk']['events'] %}
```

Hver aftale i listen har et `summary`-felt med titlen. Til en talt besked er det det eneste, der skal bruges.

## Flere kalendere

Kør `calendar.get_events` én gang for hver kalender med hver sin `response_variable`, og saml derefter listerne i templaten:

```yaml
- action: calendar.get_events
  target:
    entity_id: calendar.annette_familie
  data:
    start_date_time: "{{ today_at('00:00') }}"
    end_date_time: "{{ today_at('23:59') }}"
  response_variable: kalender_annette
```

I templaten for beskeden:

```jinja
{% set events = events_rolf + events_annette + events_louise %}
```

## Den komplette automation

```yaml
alias: "Morgenbriefing: TTS kl. 06"
mode: single
trigger:
  - platform: time
    at: "06:00:00"
action:
  - action: calendar.get_events
    target:
      entity_id: calendar.rolf_szimnau_dk
    data:
      start_date_time: "{{ today_at('00:00') }}"
      end_date_time: "{{ today_at('23:59') }}"
    response_variable: kalender
  - action: calendar.get_events
    target:
      entity_id: calendar.annette_familie
    data:
      start_date_time: "{{ today_at('00:00') }}"
      end_date_time: "{{ today_at('23:59') }}"
    response_variable: kalender_annette
  - action: calendar.get_events
    target:
      entity_id: calendar.louise_familie
    data:
      start_date_time: "{{ today_at('00:00') }}"
      end_date_time: "{{ today_at('23:59') }}"
    response_variable: kalender_louise
  - action: tts.speak
    target:
      entity_id: tts.google_ai_tts
    data:
      media_player_entity_id: media_player.hojtaler_kokken
      language: da-DK
      message: >-
        {% set dage = ['mandag', 'tirsdag', 'onsdag', 'torsdag', 'fredag', 'lørdag', 'søndag'] %}
        {% set dag = dage[now().weekday()] %}
        {% set events_rolf = kalender['calendar.rolf_szimnau_dk']['events'] %}
        {% set events_annette = kalender_annette['calendar.annette_familie']['events'] %}
        {% set events_louise = kalender_louise['calendar.louise_familie']['events'] %}
        {% set events = events_rolf + events_annette + events_louise %}
        {% set temp = state_attr('weather.forecast_home', 'temperature') %}
        {% set affald = states('sensor.affalddk_bytoften_1_naeste_afhentning') | int(99) %}
        {% set elpris = states('sensor.energi_data_service') | float(0) | round(2) %}
        {% set km = states('sensor.skoda_elroq_range') | int(0) %}
        {% set bat = states('sensor.skoda_elroq_battery_percentage') | int(0) %}
        {% set maal = states('sensor.skoda_elroq_target_battery_percentage') | int(80) %}
        {% set lader = states('sensor.skoda_elroq_charging_state') %}
        {% set ac = states('climate.skoda_elroq_air_conditioning') %}
        {% set rejsetid = states('sensor.rejsetid_vejle_travel_time') | float(0) | round(0) | int %}
        {% set normal = states('sensor.rejsetid_vejle_normal') | float(0) | round(0) | int %}
        God morgen! I dag er det {{ dag }}.
        Temperaturen ude er {{ temp }} grader.
        {% if events | length > 0 %}
        Du har {{ events | length }} aftale{% if events | length > 1 %}r{% endif %} i dag:
        {% for event in events %}{{ event.summary }}{% if not loop.last %}, {% endif %}{% endfor %}.
        {% else %}Ingen aftaler i dag.
        {% endif %}
        {% if affald == 0 %}Husk: affald hentes i dag!
        {% elif affald == 1 %}Husk: affald hentes i morgen.
        {% endif %}
        {% if km > 0 and km < 100 %}Elroq har kun {{ km }} kilometer tilbage.
        {% endif %}
        {% if lader == 'charging' %}Elroq lader: {{ bat }}% ud af {{ maal }}%.
        {% elif bat < maal %}Elroq er {{ bat }}% – har ikke nået målet på {{ maal }}%.
        {% endif %}
        {% if ac != 'off' %}Elroq varmer op.
        {% endif %}
        {% if now().weekday() < 5 %}
        {% if rejsetid > 0 %}Kørsel til arbejde tager {{ rejsetid }} minutter{% if normal > 0 and rejsetid - normal >= 5 %}, {{ rejsetid - normal }} minutter mere end normalt{% endif %}.
        {% else %}Trafikdata mangler.
        {% endif %}{% endif %}
        Elprisen er {{ elpris }} kroner per kilowattime.
```

## Tilpasning

**Kun hverdage**: tilføj en betingelse før handlingerne:

```yaml
condition:
  - condition: time
    weekday: [mon, tue, wed, thu, fri]
```

**En anden højttaler**: erstat `media_player.hojtaler_kokken` med en hvilken som helst media player-entitet i HA.

**En anden TTS-motor**: skift `tts.google_ai_tts` ud med `tts.google_translate_en_com`, hvis du vil have den gratis løsning.

**En anden elpris-sensor**: erstat `sensor.energi_data_service` med din egen sensor for spotprisen.

## Elbilens status og forvarmning

To sensorer fra MyŠkoda-integrationen fortæller i briefingen, om bilen er klar til dagen.

**Ladestatus**: briefingen siger kun noget, når der er noget at gøre. Nåede bilen sit lademål i løbet af natten, siges der ingenting.

```jinja
{% set bat = states('sensor.skoda_elroq_battery_percentage') | int(0) %}
{% set maal = states('sensor.skoda_elroq_target_battery_percentage') | int(80) %}
{% set lader = states('sensor.skoda_elroq_charging_state') %}
{% if lader == 'charging' %}Elroq lader: {{ bat }}% ud af {{ maal }}%.
{% elif bat < maal %}Elroq er {{ bat }}% – har ikke nået målet på {{ maal }}%.
{% endif %}
```

`sensor.skoda_elroq_target_battery_percentage` sættes i MyŠkoda-appen og findes direkte som sensor i HA. Bruger din elbils integration ikke et lademål, så erstat `maal` med et fast tal som `80`.

**Bekræftelse af forvarmningen**: kører en automation, der varmer bilen op, få minutter før kl. 06:00, kan briefingen bekræfte, at den faktisk gik i gang:

```jinja
{% set ac = states('climate.skoda_elroq_air_conditioning') %}
{% if ac != 'off' %}Elroq varmer op.
{% endif %}
```

Det virker, fordi opvarmningen starter kl. 05:55, fem minutter før briefingen. Kl. 06:00 er `climate.skoda_elroq_air_conditioning` enten i gang (så kommer en kort bekræftelse) eller stadig `off` (så siges der ingenting, for opvarmningsautomationen sender selv en advarsel, hvis den fejler).

## Trafikinformation

Integrationen Waze Travel Time giver en sensor med den aktuelle rejsetid, hvor trafikken er regnet med. Den kræver ingen API-nøgle. Du finder den under Indstillinger → Enheder og tjenester → Tilføj integration → *Waze Travel Time*.

Tre indstillinger afgør, om den virker. Brug `zone.home` som startpunkt. Skriver du en adresse, slår Waze den selv op, og min endte 3,3 km fra huset, så rejsetiden blev regnet fra et forkert sted. Som mål kan du kopiere koordinaterne til arbejdspladsen fra Google Maps.

Lad felterne til veje, der skal med eller udelukkes, stå tomme, medmindre du ved præcis, hvad der skal stå i dem. De sammenlignes tegn for tegn med vejnavnene i ruten, inklusive vejnummeret i parentes (`E45`, `E20 / E45`). Står der en adresse i et af dem, afviser Waze alle ruter. Sensoren bliver stående på `unknown`, og det eneste spor er en advarsel i loggen: »No routes matched your filters«. Sådan kørte min, indtil jeg gik på jagt efter fejlen. De præcise vejnavne får du ved at kalde `waze_travel_time.get_travel_times` under Udviklerværktøjer → Handlinger med start og mål. Svaret viser dem for hver rute.

Home Assistant laver entitets-id'et ud fra det navn, du giver integrationen. Jeg har omdøbt mine til `sensor.rejsetid_arbejde` og `sensor.rejsetid_arbejde_normal`, og dem bruger eksemplerne herunder.

### Hvor meget værre end normalt?

En fast grænse som »over 40 minutter« siger ikke meget, for en almindelig morgen svinger. Tilføj integrationen en gang til med samme start og mål, og slå **Realtid** fra i dens indstillinger. Den sensor giver rejsetiden på en helt almindelig dag, og forskellen er forsinkelsen:

```jinja
{% set rejsetid = states('sensor.rejsetid_arbejde') | float(0) | round(0) | int %}
{% set normal = states('sensor.rejsetid_arbejde_normal') | float(0) | round(0) | int %}
{% if now().weekday() < 5 %}
{% if rejsetid > 0 %}Kørsel til arbejde tager {{ rejsetid }} minutter{% if normal > 0 and rejsetid - normal >= 5 %}, {{ rejsetid - normal }} minutter mere end normalt{% endif %}.
{% else %}Trafikdata mangler.
{% endif %}
{% endif %}
```

Den sidste gren er lige så vigtig som resten. Min første udgave sprang sætningen over, når rejsetiden var 0, så en sensor, der ikke virkede, gjorde bare briefingen lidt kortere, og det opdagede ingen. »Trafikdata mangler« bliver opdaget næste morgen.

### Landevej eller motorvej

Jeg kan køre på arbejde ad landevejen eller ad motorvejen, og det skifter fra dag til dag, hvilken der er hurtigst. Waze sender op til fire forslag, og fra mit hus var motorvejen aldrig iblandt, heller ikke de dage, hvor Google Maps satte den øverst. Et filter vælger kun mellem de ruter, Waze sender, så det kan ikke tvinge motorvejen frem.

Løsningen er at dele motorvejsruten ved et punkt på selve motorvejen: én Waze-sensor fra hjemmet til punktet og én fra punktet til arbejdet, som lægges sammen i skabelonen. Vælg punktet på kørebanen i din egen kørselsretning. De to kørebaner ligger kun cirka ti meter fra hinanden, og et punkt på den forkerte giver en omvej med en U-vending, som viser sig som en mærkelig distance i `get_travel_times`. På landevejssensoren skriver du motorvejens navne i feltet med udelukkede veje, så den aldrig selv skifter til motorvejen.

Med tvillingerne for en normal dag bliver det seks Waze-sensorer, og det er mange opslag hvert femte minut for én sætning om dagen. Jeg har slået automatisk opdatering fra på dem alle (menuen ⋮ på integrationen → Systemindstillinger) og lader automationen opdatere dem, lige før den taler:

```yaml
  - action: homeassistant.update_entity
    target:
      entity_id:
        - sensor.rejsetid_arbejde
        - sensor.rejsetid_arbejde_normal
    continue_on_error: true
  - delay:
      seconds: 20
```

### Uheld og vejarbejde

Waze-integrationen giver rejsetiden, men ikke grunden til en forsinkelse. Vejdirektoratets trafikkort (trafikkort.vejdirektoratet.dk) henter sine hændelser fra et offentligt JSON-feed, som ikke kræver nøgle. Feedet er ikke dokumenteret, så det kan ændre sig uden varsel. Denne REST-sensor beholder kun aktive hændelser inden for 1,5 km af din rute. Erstat `ROUTE` med punkter langs din egen rute, cirka ét pr. kilometer, som `[breddegrad, længdegrad]`:

```yaml
rest:
  - resource: https://storage.googleapis.com/trafikkort-data/geojson/big-screen-events.json
    scan_interval: 300
    timeout: 30
    sensor:
      - name: Trafikmeldinger arbejde
        value_template: >-
          {#- punkter langs ruten, cirka 1 km imellem -#}
          {%- set ROUTE = [[56.0000, 9.0000], [56.0090, 9.0010], [56.0180, 9.0030]] -%}
          {%- set ns = namespace(seen=[], out=[]) -%}
          {%- for fc in value_json | reverse -%}
          {%- for f in fc.features -%}
          {%- set p = f.properties -%}
          {%- set id = p.featureId | default('') | regex_replace('\\.\\d+$', '') -%}
          {%- if id not in ns.seen -%}
          {%- set ns.seen = ns.seen + [id] -%}
          {%- set c = f.geometry.coordinates -%}
          {%- if c[0] is not number -%}{%- set c = c[0] -%}{%- endif -%}
          {%- set lon = c[0] | float(0) -%}{%- set lat = c[1] | float(0) -%}
          {%- set near = namespace(v=false) -%}
          {%- for q in ROUTE -%}{%- if ((lat - q[0]) * 111.2) ** 2 + ((lon - q[1]) * 62.9) ** 2 < 2.25 -%}{%- set near.v = true -%}{%- endif -%}{%- endfor -%}
          {%- set h = p.header | default('') | regex_replace('&lt;[^&]*&gt;\\s*', '') | regex_replace('<[^>]*>\\s*', '') | replace('&amp;', '&') | trim -%}
          {%- set start = strptime(p.beginPeriod | default(''), '%d-%m-%Y kl. %H:%M', none) -%}
          {%- set fresh = start is not none and (as_timestamp(now()) - as_timestamp(as_local(start))) < 43200 -%}
          {%- if p.suspended | string | lower == 'false' and near.v and fresh and h not in ns.out -%}
          {%- set ns.out = ns.out + [h] -%}
          {%- endif -%}{%- endif -%}
          {%- endfor -%}{%- endfor -%}
          {{ (ns.out | join('. ') or 'Ingen')[:250] }}
```

To detaljer tog længst tid. Hver hændelse findes i flere versioner, hvor id'et ender på `.1`, `.2` og så videre, og kun den nyeste fortæller, om hændelsen er overstået (`suspended`). Skabelonen grupperer derfor på id'et uden endelsen og bruger den nyeste. Og feedet rummer kun omkring et døgns historik, så test mod en hændelse, der er i gang nu, og ikke en fra i går.

Briefingen læser så sensoren op, når den står på andet end `Ingen`:

```jinja
{% set trafik = states('sensor.trafikmeldinger_arbejde') %}
{% if trafik not in ['Ingen', 'unknown', 'unavailable'] %}Trafikmelding: {{ trafik }}.{% endif %}
```

## Hvorfor `tts.speak` og ikke den gamle handling

Fra Home Assistant 2024 kaldes `tts.speak` på selve TTS-motorens entitet med `media_player_entity_id` som datafelt. Den gamle handling `tts.google_translate_say` virker stadig, men er forældet. Det nye mønster holder motor og afspiller adskilt, så du let kan skifte den ene uden den anden.

`tts.google_ai_tts` kommer fra integrationen **Google Generative AI**, den samme, der står bag Gemini som samtaleagent i Home Assistant. Den kræver en API-nøgle fra Google AI Studio, men stemmen lyder naturlig og menneskelig sammenlignet med den robotagtige lyd fra den gratis Google Translate TTS.
