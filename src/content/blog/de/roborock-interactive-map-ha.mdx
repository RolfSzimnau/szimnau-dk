Die Roborock-Integration ist direkt in HA eingebaut, kein HACS nötig. Hinzufügen, mit dem Roborock-Konto einloggen (ein Roborock-Cloud-Konto ist erforderlich), der Staubsauger erscheint. Was einem niemand sagt: Das Interessante kommt von einer separaten HACS-Karte, die die Live-Karte rendert.

## Die Roboter-Ansicht auf dem Wandtablet

Auf dem Wandtablet nimmt die Karte die linke Hälfte ein, alles andere steht in einer Spalte rechts. In den Bildern ist die Karte unscharf, weil sie meinen Grundriss zeigt. Der Code weiter unten stammt aus der ersten Version dieses Aufbaus, seine Entitätsnamen und die Prozent-Sensoren sind also veraltet.

### Karte: Zonen und Ziel anfahren

Auf der Karte lässt sich eine Zonenreinigung zeichnen oder der Roboter an eine bestimmte Stelle schicken. Die Zonenreinigung ist ein Rechteck, das du auf die Karte ziehst, das Anfahren eines Ziels ein einzelnes Antippen. Das Schloss in der Ecke sperrt Verschieben und Zoomen, damit ein versehentliches Anstoßen die Karte nicht verschiebt. Die Kalibrierung kommt aus dem Kartenbild selbst, du setzt also keine Punkte von Hand, und `two_finger_pan` sorgt dafür, dass ein Wischen mit einem Finger die Seite scrollt statt der Karte.

```yaml
type: custom:xiaomi-vacuum-map-card
entity: vacuum.robo
vacuum_platform: Roborock
map_source:
  camera: image.robo_map
calibration_source:
  camera: true
map_modes:
  - template: vacuum_clean_zone
  - template: vacuum_goto
two_finger_pan: true
```

### Raumschaltflächen und Saugstufe

Die vier Schaltflächen (Full, Living, Bedroom, Kitchen) drücken Button-Entitäten, die die Roborock-Integration aus den Routinen anlegt, die in der Roborock-App gespeichert sind. Ein Druck ist ein einziger `button.press`-Aufruf, du musst also keine Raum-IDs nachschlagen. Die Kitchen-Schaltfläche startet eine Routine, die ich „After meals“ genannt habe. Die Chips darunter stellen die Saugstufe ein: Quiet, Balanced, Turbo oder Max, und die aktive ist farbig hervorgehoben.

![Die rechte Spalte der Roboter-Ansicht: Status mit Akku- und Flächen-Chips, Raumschaltflächen, Chips für die Saugstufe, Wartung mit verbleibenden Stunden und der Wischmodus](/blog-images/roborock-tablet-cards.webp)

### Wartung in Prozent und Stunden

Filter, Seitenbürste, Hauptbürste und Sensoren zeigen jeweils einen Prozentwert und die verbleibenden Stunden, etwa „91% - 137h of 150h“. Meine Version der Integration meldet nur die verbleibenden Stunden, deshalb teilt das Template durch die Nennlebensdauer des Teils: 150 h beim Filter, 200 h bei der Seitenbürste, 300 h bei der Hauptbürste und 30 h bei den Sensoren.

```yaml
secondary: >
  {% set left = states('sensor.robo_filter_time_left') | float(0) %}
  {{ ([[left / 150 * 100, 0] | max, 100] | min) | round(0) | int }}% - {{ left | round(0) | int }}h of 150h
```

### Wischen

Der Wischmodus ist eine Select-Entität. Die Zeile für die Intensität erscheint nur, wenn der Roboter einen Wert meldet, und blendet sich aus, solange der Zustand unbekannt ist. So hat die Ansicht keine Zeile, in der „Unknown“ steht.

## Die Integration

Cloud-Polling mit 5-Sekunden-Aktualisierung. Lokale Kommunikation ist möglich, erfordert aber das Extrahieren von Schlüsseln aus der Geräte-Firmware. Das habe ich mir gespart. Für alles Wichtige (Reinigung starten, Akku prüfen, Raumsegmente) ist Cloud-Polling schnell genug.

Entitäten nach der Einrichtung:

```
vacuum.roborock_s5_max
sensor.roborock_battery
sensor.roborock_status
sensor.roborock_last_clean_area
sensor.roborock_main_brush_left    — verbleibende Lebensdauer in Prozent
sensor.roborock_side_brush_left
sensor.roborock_filter_left
sensor.roborock_sensor_dirty_left
```

## Die Kartenkarte

`custom:xiaomi-vacuum-map-card` (HACS) ist das, was diese Einrichtung wirklich nützlich macht. Sie rendert die Live-Karte mit beschrifteten Raumzonen, und ein Tippen auf einen Raum startet die Reinigung genau dieses Segments.

```yaml
type: custom:xiaomi-vacuum-map-card
entity: vacuum.roborock_s5_max
map_source:
  camera: camera.roborock_map
calibration_source:
  auto: true
rooms:
  - id: 16
    name: Wohnzimmer
    icon: mdi:sofa
  - id: 17
    name: Küche
    icon: mdi:silverware-fork-knife
  - id: 18
    name: Schlafzimmer
    icon: mdi:bed
  - id: 19
    name: Büro
    icon: mdi:desk
map_modes:
  - template: vacuum_clean_segment
  - template: vacuum_goto
```

Raum-IDs finden: Entwicklertools → Template, `{{ state_attr('vacuum.roborock_s5_max', 'room_list') }}` auswerten. Die IDs sind ganze Zahlen, die beim Erstellen der Karte in der App vergeben wurden. Meine fangen bei 16 an, deine werden wahrscheinlich anders sein.

Die Kartenkarte lebt in einem Glas-`stack-in-card`. Kartenkarten brauchen `border-radius: 0` auf der inneren Karte, und der äußere Container braucht `overflow: hidden`. Sonst stehen die quadratischen Ecken der Karte aus der abgerundeten Glasumhüllung heraus.

```yaml
type: custom:stack-in-card
card_mod:
  style: |
    ha-card {
      background: rgba(255,255,255,0.05) !important;
      backdrop-filter: blur(15px) !important;
      border: 1px solid rgba(255,255,255,0.10) !important;
      box-shadow: 0 8px 32px rgba(0,0,0,0.3) !important;
      border-radius: 28px !important;
      overflow: hidden !important;
    }
    ha-card::before { display: none !important; }
cards:
  - type: custom:xiaomi-vacuum-map-card
    # ...
    card_mod:
      style: |
        ha-card { border-radius: 0; box-shadow: none; border: none; }
```

## Wartungssensoren

Die Bürsten- und Filtersensoren zählen von 100% auf 0% herunter. Ich ignorierte sie zu lange und bekam dann eine Warnung, dass die Hauptbürste bei 8% war. Sie war *viel* abgenutzter, als eine Prozentzahl vermuten ließ.

Farbige Indikatorkarten für jede Komponente mit `custom:mushroom-template-card` (HACS, Mushroom-Suite) und `card_mod` (HACS):

```yaml
type: custom:mushroom-template-card
primary: "{{ states('sensor.roborock_main_brush_left') }}%"
secondary: Hauptbürste
icon: mdi:brush
icon_color: >
  {% set pct = states('sensor.roborock_main_brush_left') | int(100) %}
  {% if pct > 40 %}green{% elif pct > 20 %}orange{% else %}red{% endif %}
```

Und eine persistente Benachrichtigung (kein Push, mein Telefon muss wegen einer Bürste nicht klingeln), wenn etwas unter 20% fällt:

```yaml
alias: Roborock — Wartungswarnung
trigger:
  - platform: numeric_state
    entity_id: [sensor.roborock_main_brush_left, sensor.roborock_filter_left,
                sensor.roborock_side_brush_left]
    below: 20
action:
  - service: persistent_notification.create
    data:
      title: "Roborock — Wartung prüfen"
      message: >
        {{ trigger.entity_id | replace('sensor.roborock_','') | replace('_left','')
           | replace('_',' ') | title }} bei {{ trigger.to_state.state }}%.
      notification_id: roborock_maintenance
```

## Die Automatisierung, die ich täglich nutze

Reinigen während ich weg bin, andocken bevor ich zurückkomme:

```yaml
alias: Roborock — Reinigen bei Abwesenheit
trigger:
  - platform: state
    entity_id: person.rolf
    to: not_home
    for:
      minutes: 5
condition:
  - condition: time
    after: "09:00:00"
    before: "18:00:00"
  - condition: state
    entity_id: vacuum.roborock_s5_max
    state: docked
action:
  - service: vacuum.start
    target:
      entity_id: vacuum.roborock_s5_max

alias: Roborock — Andocken bei Rückkehr
trigger:
  - platform: state
    entity_id: person.rolf
    to: home
condition:
  - condition: state
    entity_id: vacuum.roborock_s5_max
    state: cleaning
action:
  - service: vacuum.return_to_base
    target:
      entity_id: vacuum.roborock_s5_max
```

Die 5-Minuten-Verzögerung beim Abgang ist wichtig. Ohne sie löst ein kurzer GPS-Ausreißer eine Reinigung aus, und der Staubsauger ist auf halbem Weg durch die Küche wenn ich zwei Minuten später wieder reinkomme.

Die Andock-bei-Rückkehr-Automatisierung hat mich genau einmal davor bewahrt, im Dunkeln auf den Staubsauger zu treten. Es war es wert.
